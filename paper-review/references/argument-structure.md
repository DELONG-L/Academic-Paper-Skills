# Argument and Paragraph Structure Review

Use for a draft whose argument, paragraph placement, or cross-section repetition
needs review. Review the requested section or manuscript before line editing.
Do not require this workflow for a sentence-level edit or a formatting check.

## Establish Scope and the Argument

Read the available abstract, introduction, headings, and relevant conclusions
to identify the paper's central claims and each section's contribution. Then read
the body needed to assess those claims; topic sentences alone are not evidence
that the full argument works. Record what was actually inspected.

Express the argument as claims supported by evidence and connected by reasoning.
Independent findings can form parallel branches; do not invent a dependency.
Measurement, replication, negative findings, synthesis, and theory can each carry
the contribution. A performance advantage is not a prerequisite for relevance.

For a local section, use available context and report only local conclusions.
Missing full-paper context does not prevent useful local editing. Do not assert
global redundancy or whole-paper closure from an excerpt.

## Review Paragraphs by Their Contribution

For each paragraph in scope, identify its information and function. A paragraph
may define an object, establish a premise, report evidence, derive a consequence,
explain a method, or provide needed navigation. It need not fit a standard pattern.

Choose the action that addresses an observed problem:

| Action | Use when | Result to specify |
|---|---|---|
| Keep | The paragraph contributes useful information in the right place | No rewrite needed |
| Tighten | Useful information is obscured by repetition or framing | What content remains |
| Merge | Adjacent or related paragraphs repeat setup or split one argument | Destination and retained information |
| Move | The reader needs the information earlier or in another section | Source, destination, and dependency changes |
| Split | Different claims or functions obscure each other | New paragraph roles and order |
| Delete | The text adds no needed information, reasoning, or navigation | Why nothing necessary is lost |
| Resolve a substantive issue | The problem is a false premise, unsupported claim, or author decision | Exact gap and evidence or decision needed |

Separate information from phrasing. A paragraph containing both filler and a
unique result is a tightening candidate, not an empty paragraph. No independent
need for every sentence to assert a new empirical fact: definitions, derivations,
topic sentences, and useful transitions can all carry the argument.

During structural editing, track the retained information
and its location for moves, merges and removals. For empty filler, explicitly
record that no scientific information needs a surviving location. Material
caveats remain scientific content; a ritual disclaimer about an unclaimed goal
is not a new fact to preserve. Leave low-confidence substantive decisions explicit.

Do not add paragraphs to answer objections nobody has raised. Correct an
overbroad claim directly. Use
`../../paper-writing/references/over-defensive-writing.md` for the distinction
between necessary scientific content and anticipatory self-defense.

## Resolve Cross-Section Repetition

Compare propositions, not repeated keywords. Check whether two passages make
the same claim under the same conditions; different populations, metrics,
evidence roles, or exceptions can make similar wording necessary.

For each proposed consolidation, inspect every affected source and destination.
Record the information to retain, its final location, and the citations,
definitions, values, or cross-references that travel with it. If a location is
unavailable, describe a conditional recommendation rather than claiming a safe
deletion. A paragraph can be omitted from the main text only if doing so does
not conceal evidence needed to assess the paper's claims.

Keep repetition that helps a reader: an abstract can stand alone; a later section
may restate a distant definition; separate responses may each need an answer.
Judge the cost of looking back and the role of the repetition. There is no
one-location quota or section-distance threshold.

Typical decisions:

- Put a shared design rationale in Methods; let Results explain observations.
- Keep a short recap when a later argument otherwise requires reconstructing a
  distant definition. Include enough meaning, not just an opaque label.
- Move lengthy derivation detail when the main text retains the premises,
  conclusion, and a usable pointer. Keep essential proof steps where needed.
- Preserve adverse comparisons and failed conditions that affect the claim;
  do not classify inconvenient evidence as narrative clutter.

## Check the Revised Argument

Read the proposed or edited sequence as a reader encountering it for the first
time. Check that definitions precede use, premises support conclusions, each
promised contribution receives evidence, and the abstract and conclusion describe
what the body establishes. Look for missing links as well as repetition.

Organize by what the work establishes, rather than implementation chronology,
unless chronology is itself evidence (for example, a longitudinal study or
process analysis). If the strongest evidence contradicts an agreed mainline,
identify the mismatch and an evidence-supported alternative; do not silently
replace the author's research objective or hide the conflicting result.

## Deliver and Continue

For a reader-oriented check, ask what the document itself lets a reader recover:
the central finding, the evidence supporting it, and the definitions needed to
follow the inference. Locate the answers in the text. This tests comprehension,
not hypothetical objections to preempt in the manuscript. If a separately
authorized fresh reader/evaluator is available, give only the draft and these
questions; otherwise describe the result as self-review, not independent testing.

For an audit, return located findings and a concrete edit plan. A useful compact
record is:

`location | function/information | action | reason | destination/retained content`

Add a short argument map and relocation list only when the task benefits from
them. For long work, reuse existing notes and record reviewed sections plus
source revisions so the next pass can resume. No fixed file names or mandatory
empty ledgers.

When editing is authorized, hand the located plan and evidence to `paper-writing`
and complete the changes in the same task. Resolve structure first, then polish
the retained text. Recheck affected references and build/render changes where
applicable. Finish with `revision-closure.md` for a substantial review; a local
edit receives a local completion statement.
